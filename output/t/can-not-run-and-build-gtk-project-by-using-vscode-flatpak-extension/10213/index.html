So, as I understand it, here is the issue:

When building a development version, you set the application id to use a .Devel suffix. That’s a good idea, however since your code loading the GSettings uses the application id, it expects a schema for org.xinux.EIMZOManager.Devel.

But your GSettings configuration doesn’t provide a GSettings schema for the id org.xinux.EIMZOManager.Devel, only for org.xinux.EIMZOManager.

In your meson build file for the data there seems to be a configuration that would replace @app-id@ for the current application id, so try to replace the id in your GSettings file with this.

I know flathub/flatpaks does technically have beta channels, but in my opinion r…ight now they don't make a great UX. From my understanding to install a Flatpak from a beta channel you have to do the following, ### Install Beta Flatpaks 1. Add the flathub beta repo _flatpak remote-add flathub-beta https://flathub.org/beta-repo/flathub-beta.flatpakrepo_ 2. Install the app using the repo beta option _flatpak install --user flathub-beta org.godotengine.Godot_ 3. And then you can run the beta app using _flatpak run org.godotengine.Godot//beta_ Now the great thing is beta and stable channel apps can be installed in parallel. However it really feels like bad ux in comparison to Snaps. ### Install Beta Snaps 1. Install the beta snap_sudo snap install skype --channel=insider_ 2. Then you can run it. However it should be noted that you can not install a beta snap and a stable snap of the same package on the same machine. ### Where to go from here I would love to see a way to install a beta flatpak in a much easier way. Something like _flatpak install --user flathub org.godotengine.Godot --channel beta_ Simple clean, no need to add a beta repo, and these beta channels can be advertised on Flathub itself, just like snaps can show they have beta/insider/other release channels right on Snapcraft.

It’s correct to use a different ID in the sense that we don’t allow arbitrary branches. Apps in Flathub beta must have beta as their branch, and apps in Flathub stable must have stable as their branch. (Firefox has an exemption from this check but still)

But you are right, doing a org.mozilla.firefox//nightly is technically possible with Flatpak and close to a channel feature.

The problem with multiple branches is that you have to manually start them from the CLI if you have multiple branches installed.
